## Архитектурные особенности

### Декораторы и безопасность данных
Для обеспечения стабильности и защиты от критических сбоев ключевые операции базы данных обернуты в специализированные декораторы:
* `@handle_db_errors` — Глобальный обработчик исключений. Перехватывает ошибки отсутствия файлов (`FileNotFoundError`), неверных ключей (`KeyError`) и ошибок валидации (`ValueError`), не позволяя приложению аварийно завершить работу при некорректном поведении.
* `@confirm_action("название")` — Фабрика декораторов контроля доступа. Запрашивает интерактивное подтверждение у пользователя `[y/n]` перед выполнением потенциально опасных деструктивных команд (таких как `drop` и `delete`).

### Механизм кэширования запросов
В операцию выборки данных (`select`) интегрировано кэширование на базе замыканий (вызов функции `create_cacher`).
* **Принцип работы:** При первом выходе уникального поискового запроса данные считываются с физического диска, парсятся из JSON и сохраняются в изолированный словарь внутри замыкания. Повторные идентичные запросы мгновенно возвращают результат из оперативной памяти, минуя операции ввода-вывода (I/O).
* **Инвалидация кэша:** При совершении любых транзакций, изменяющих состояние данных или структуры БД (`create`, `drop`, `insert`, `update`, `delete`), кэш автоматически сбрасывается и инициализируется заново, гарантируя актуальность последующих выборок.

## Управление таблицами
Внутри консольного интерфейса доступны следующие команды:

* `create_table [table_name] [col1:type col2:type ...]` - Создать новую таблицу. Столбец `id:int` добавляется автоматически в начало структуры (если его нет). 
Допустимые типы данных: `int`, `str`, `bool`. Допускается создание пустой таблицы (в ней будет только `id`).
* `list_tables` - Вывести текущую структуру всех таблиц базы данных.
* `drop_table [table_name]` - Удалить существующую таблицу из метаданных.
* `exit` - выход из программы.
* `help` - Завершить работу программы.

## CRUD-операции

Для работы с данными внутри созданных таблиц используются стандартные операции создания, чтения, обновления и удаления. Данные каждой таблицы сохраняются автономно в отдельные файлы внутри директории `data/` в формате JSON.

### Доступные команды

* `insert into <table_name> values (<val1>, <val2>, ...)` - Добавление новой записи в таблицу. `id` - автоинкремент на основе последней записи. Если в строковых значениях присутствуют пробелы, обязательно оборачивайте их в кавычки.
* `select from <table_name> (where <field> = <value>)` - Вывод содержимого таблицы в виде структурированной текстовой таблицы PrettyTable. Блок фильтрации `where` является необязательным.
* `update <table_name> set <field> = <value> (where <field> = <value>)` - Обновление полей в записях, удовлетворяющих указанному условию.
* `delete <table_name> (where <field> = <value>)` - Удаление записей из таблицы. При вызове команды без блока `where` происходит полная очистка содержимого таблицы.
